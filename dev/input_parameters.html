Input Parameters#

What each argument of read_data() and get_obs() means is written once, here: the two functions come first, then one section for each argument.

read_data(SID[, instruments, group, lvl, ...])

Read data from an instrument at a site.

get_obs(SID[, pollutants, format, group, ...])

Get observations from a site.

uataq.read_data(SID, instruments='all', group=None, lvl=None, time_range=None, num_processes=1, file_pattern=None)[source]#

Read data from an instrument at a site.

Parameters:

  • SID (str) – The site ID.

  • instruments (str | list[str] | tuple[str] | set[str] | 'all') – The instrument(s) to read data from.

  • group (str | Mapping[str, str] | None) – The research group to read data from. A name applies to every instrument; a mapping of instrument name to group name sets it per instrument. Default None selects each instrument’s group automatically (see uataq.instruments.Instrument.resolve_group()).

  • lvl (str | None) – The data level: 'raw', 'qaqc', 'calibrated' or 'final'. 'final' is the ready-to-share level, with the pipeline’s default flags applied; the lower levels are for finer control. Which to use depends on how clean the data need to be for what you are doing, and on how much control you want over the QAQC. Default None reads the highest level the instrument has. See Processing Level.

  • time_range (str | list[Union[str, dt.datetime, None]] | tuple[Union[str, dt.datetime, None], Union[str, dt.datetime, None]] | slice | None) – The time range to read data. Default is None which reads all available data.

  • num_processes (int | 'max') – The number of processes to use. Default is 1.

  • file_pattern (str | None) – A string pattern to filter the file paths.

Returns:

The data.

Return type:

dict[str, pd.DataFrame]

Get observations from a site.

Parameters:

  • SID (str) – The site ID.

  • pollutants (str | list[str] | tuple[str] | set[str] | 'all') – The pollutant(s) to get observations for.

  • format ('wide' | 'long') – The format of the data. Default is ‘wide’.

  • group (str | Mapping[str, str] | None) – The research group to read data from. A name applies to every instrument; a mapping of instrument name to group name sets it per instrument. Default None selects each instrument’s group automatically (see uataq.instruments.Instrument.resolve_group()).

  • time_range (str | list[Union[str, dt.datetime, None]] | tuple[Union[str, dt.datetime, None], Union[str, dt.datetime, None]] | slice | None) – The time range to get observations. Default is None which gets all available data.

  • num_processes (int | 'max') – The number of processes to use. Default is 1.

  • kwargs – Additional keyword arguments to pass to the site’s get_obs method.

Returns:

The observations, from the final level (see uataq.read_data() to read another level).

Return type:

pd.DataFrame

SID#

SID is the site identifier for a UATAQ site. It is a key in the configuration file, such as WBB; case does not matter. The Sites and instruments page lists them.

Instruments#

instruments is a single instrument name or a list of instrument names. The instrument name is a key under the site’s instruments in the configuration (listed on the Sites and instruments page).

Pollutants#

pollutants is a single pollutant name or a list of pollutant names. The pollutant name is a capitalized molecule abbreviation.

Research Group#

group is the research group that collected the data. It is a string that corresponds to a key in the uataq.filesystem.groups dictionary, or a mapping of instrument name to group name to choose per instrument.

With group=None (the default), each instrument picks its own group: the default group (lin) when it operates the instrument, otherwise the configured operator. When the groups’ archives cover different periods (the instrument’s group_dates in the configuration), a time range that crosses a boundary is read from each group in turn and the pieces are concatenated in time. For example, TRX01 ozone comes from lin through October 2017 and from horel after that. Naming a group reads the whole range from that group.

Processing Level#

lvl is the processing level of the data. Available levels, from least to most processed, are:

  • raw : Raw data.

  • qaqc : QAQC flags applied to data. Flagged rows are kept, with their flag in QAQC_Flag.

  • calibrated : Calibrated data. (Only available for instruments which receive calibration in post-processing.)

  • final : Finalized data, with the pipeline’s default flags applied. (Flagged data and measurements of calibration tanks are dropped.)

final is the ready-to-share level: it can go to people outside the group as it is. The lower levels (raw, qaqc and calibrated) are for finer control. Which one to use depends on how clean the data need to be for what you are doing, and on how much control you want over the QAQC.

get_obs() always reads the final level. read_data() reads the level you give it. With no lvl it reads the highest (most processed) level the instrument has. Your first month of data shows the same day at final and at qaqc, and Columns and flags says what each level holds.

Time Range#

time_range filters the returned data to the specified time range. Times are UTC, and so are the times in the data. To read a month in local time, see Your first month of data.

There are three primary formats for time_range:

  1. None: Returns all available data.

  2. Single string in ISO8601 format (UTC), down to fractions of a second:

    • The string is interpreted as a range from the start of the string to the start of the next time unit.

    • Examples:

      • ‘2020’ represents the year 2020.

      • ‘2020-01’ represents January 2020 to February 2020.

      • ‘2020-01-01’ represents January 1st, 2020 to January 2nd, 2020.

      • ‘2020-01-01T12’ represents January 1st, 2020 from 12:00 to 13:00.

      • ‘2020-01-01T12:30’ represents January 1st, 2020 from 12:30 to 12:31.

      • ‘2020-01-01T12:30:45.5’ represents 12:30:45.5 to 12:30:45.6 (one unit of the last digit given).

    • Dashes and colons may be omitted (‘20200101’), and a trailing ‘Z’ or ‘+00:00’ is accepted. Other strings, including other UTC offsets, raise a ValueError.

  3. List, tuple, or slice of two datetime-like objects:

    • Datetime-like objects include datetime objects, Timestamp objects, and strings in ISO8601 format.

    • The first object is the start of the range and the second object is the end of the range. The range is inclusive of the start and exclusive of the end. An end given as a string is taken as the end of the period it names, as above, so ['2020-01-01', '2020-01-31'] includes all of January 31st.

    • The use of None in place of a datetime-like object will set the range to be unbounded in that direction.

Time zones#

The examples in this section read the UATAQ archive, which is only available on CHPC. They are shown as code and are not run when the documentation is built; the output is from runs on CHPC on 12 October 2026.

Times have no time zone attached. A string with an offset other than Z or +00:00 is an error that says so:

>>> import uataq
>>> uataq.get_obs("WBB", "CO2", time_range="2025-06-01T00:00-06:00")
Traceback (most recent call last):
  ...
ValueError: Invalid time string '2025-06-01T00:00-06:00'. Expected ISO 8601 in UTC, e.g. '2024', '2024-01', '2024-01-15', '2024-01-15T12:30:45'.

A pandas Timestamp must not carry a time zone either. One that does gives an error that does not say what to do:

>>> import pandas as pd
>>> start = pd.Timestamp("2025-06-01", tz="America/Denver")
>>> stop = pd.Timestamp("2025-07-01", tz="America/Denver")
>>> uataq.get_obs("WBB", "CO2", time_range=[start, stop])
Traceback (most recent call last):
  ...
TypeError: Cannot compare tz-naive and tz-aware timestamps

The same happens with tz="UTC". Convert the times to UTC and take the time zone off:

>>> utc = [t.tz_convert("UTC").tz_localize(None) for t in (start, stop)]
>>> utc
[Timestamp('2025-06-01 06:00:00'), Timestamp('2025-07-01 06:00:00')]
>>> len(uataq.get_obs("WBB", "CO2", time_range=utc))
250685

That reads exactly June in local time, the same 250,685 rows as the cut in A month in local time. Both ways are right; use the one you find clearer.

Where a range ends#

An end given as a Timestamp stops at that instant, so the same end given as a string gives a longer range:

>>> a = uataq.get_obs("WBB", "CO2", time_range=["2025-06-02T06", "2025-06-03T06"])
>>> a.index[-1]
Timestamp('2025-06-03 06:59:53')
>>> b = uataq.get_obs(
...     "WBB", "CO2", time_range=[pd.Timestamp("2025-06-02T06"), pd.Timestamp("2025-06-03T06")]
... )
>>> b.index[-1]
Timestamp('2025-06-03 05:59:58')

So the string range is an hour longer. When you want an end at an exact time, give it as a Timestamp.

Number of Processes#

num_processes is the number of processes to use when reading data from each instrument. The default is 1.

  • If num_processes is set to 1, the data is read serially.

  • Setting num_processes to a number greater than 1 will read the data in parallel using the minimum of num_processes and the number of files for an instrument.

  • Setting num_processes to ‘max’ will use the minimum of the number of files for an instrument and the number of available CPU cores.

    Warning: Frequent use of num_processes='max' may upset your fellow node users.

File Pattern#

file_pattern is a string that is used to filter the files. The primary use for this parameter is to filter raw lin gps data by nmea sentence type. The default is None.
